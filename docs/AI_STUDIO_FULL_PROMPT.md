## 2. 原有系统功能与不可破坏的契约

这是一个以平板为第一屏、面向中国高中物理电磁学教学和高考综合题讲解的完整 React/TypeScript/Vite PWA。它不是纯展示页面。项目目前报告具备：

- **16 个完整物理模型**：P01–P08、I01–I08。P01 包含真实 WebGL 3D 螺旋轨迹和 2D 模式；其余包含带电粒子、复合场、电磁感应、双杆、发电机等。
- **132 道原创基础题，9 道内置完整案例（C01–C08、A17-01）**，学生有题目→建模→统一舞台仿真→逐问解析→答案核对→变式探索的完整流程。
- `WholeProblemLab.tsx` 和真实求解器事件时间轴；跨求解器电加速→有限磁场→无场屏幕状态连续交接；答案随条件变化重算，不显示过期的标准答案。
- 同一个学生舞台支持 **1–5 个粒子**，共享全局物理时钟 `tGlobal`、粒子各有 `launchTime`，在播放中只修改 A 不可暂停 B/C，公共场更改按既有语义整体重演。
- **所有物理数值参数保留滑块 + 安全数学表达式输入**：`√2`、`√3/2`、`π`、`1/3`、`3e-6`、括号等；输入框的合法值可超滑块范围，不能偷偷 clamp；非法输入不能变更已生效参数。解析器严格白名单，不能调用 `eval/new Function`。
- I01/I04/I05/I08 等人工调磁、手动转动/推拉是真实时间会话；力、电流与能量图表基于真实状态，不能把手势暂停/触摸事件重构成无物理意义的动画。
- 教师工作台：`/#/teacher/problems`、`/#/teacher/problems/:draftId/edit`、`/#/teacher/problems/:draftId/preview`；私有草稿由白名单适配器编译；没有任意脚本执行；用户本地数据与学生进度不得被抹除。
- 学习路径、题库筛选、场景 v2 保存/导入导出、PWA 离线与版本缓存、hash 深链；P01 懒加载 Three.js；`/#/device-check` 真实设备检测入口。
- **5 条真实高考题索引均为未授权、未核验的链接元数据**。禁止添加原卷题干/图片/解析或捏造官方来源。现有原创建模题与真题必须明确区别。
- 上一轮用户报告回归为 593/593 Vitest、180/180 Playwright、3/3 PWA；数字仅作保护基线，除非实际运行不得宣称当轮已经通过。

### 绝对禁止的变化

- 不可删除 16 个模型任何一页、改动其路由/输入输出、写死答案或用静态画面冒充仿真。
- 不可在未经专项审查的情况下改 `src/physics/**`、各模型真实状态求解器、数学 parser/domain validator、场景序列化 schema、P07 真实板/屏事件、P08 反求、I05/I07 能量、P01 3D 物理公式。
- 不可破坏运动连续性、时间轴、碰撞与边界事件；不可因 UI 动画帧率更改物理求解精度或物理时间。
- 不可删除、跳过、修改旧测试以让改动“看似成功”。不可全局替换 `localStorage` 键或刷新所有 PWA 缓存以修复单点问题。
- 不要为了使用 Gemini API 而在学生端引入不必要的外部请求/服务器/登录/费用。当前离线核心功能必须在**断网后**继续运行。若确实建议未来 AI 辅导特性，先作为独立非必需可选方案报告，不要默认实现。

若某项 UX 更改不得不碰受保护 API：**先解释为何不可避免、可能破坏的功能、需要 Codex 编写的物理回归，然后将其从本批 UI 提交中剥离**。

## 3. Track A：高质量、学生友好的 UI/UX 收口

### 3.1 目标产品风格

这是**专业、清爽、学术可信、适合教师投屏和学生平板操控**的教学实验室。希望整体视觉统一，动画与参数清晰，兼顾中文数学公式和物理单位。避免套用复杂 SaaS 仪表盘模板、大面积无信息的渐变卡片、浮夸 3D 装饰、挤压物理舞台的悬浮面板。优先提升真实教学效率，不要仅仅换色。

### 3.2 分批改善，而不是一轮推翻全站

**批次 0：使用现有页面做只读 UX 审计**：首页、16 模型入口、P02/P07/P08、I05/I07/I08、`/#/cases/:caseId`、学习路线、教师题目编辑器、数学输入控件、设备检测。说明哪些问题来自现有代码截图、哪些只是推测。生成优先级列表，限于当前工具实际能复现的证据。

**批次 1（必须真实实现）**：

1. 首页：突出“按知识点学习、从整题开始、自由实验、教师备课”四条路径，并减少入口视觉噪声；不移除原路由。
2. 实验室布局：确保**物理舞台始终有足够可视面积**；参数区、数据区、轨迹/教师图层切换清楚，播放/暂停/重置及时间控制不易误触。
3. 平板横竖屏：至少在 `1194×834`、`1024×768`、`768×1024`、一个 Android 平板纵向近似视口下进行布局审查；确保重要按钮不溢出、不被虚拟键盘覆盖，合理处理 safe-area、地址栏高度、底部工具条和滚动容器。
4. 数学输入：保留既有 `ParamSlider` 提交与撤销语义、原值提示、单位和 `√/π` 快捷输入，至少 **44 CSS px** 触控目标；聚焦时不应自动重置物理时间轴。不要将合法超滑块范围值改回滑块上限。
5. 整题案例：同屏读题、真正的完整物理舞台、事件索引与逐问推导要能在平板触控中切换；学生可以快速定位对应事件时刻，返回后保留已经完成的小问。

**批次 2（在批次 1 测试通过后）**：

6. 教师题目编辑器：字段分组清楚；来源/核验/授权状态显眼；输入题干和公式与预览之间切换简单，错误提示具体。保护私有草稿和 KaTeX `trust:false` 安全策略。
7. 课堂教师视图：关键速度、加速度、磁通、电流、能量、圆心、事件可选择显示，不得全屏充满不可读标签；支持隐藏答案、重点步骤高亮。
8. 视觉一致性：排版、配色、组件状态、hover/focus、错误反馈、图标、空态、加载态；适当视觉降级只减少辅助层的采样/装饰，不更改求解器结果。
9. 无障碍：明显键盘焦点、表单标签与 aria、色盲可区分的轨迹、数学公式阅读顺序，符合平板阅读字号和足够对比度；读屏真机仍需真实验收。

### 3.3 必须保留的具体交互

- 同一 P07 舞台 5 粒子轨迹与不同颜色；拖动 A 的发射方向，仅 A 重发射，其他粒子全局时钟继续。
- P08 移动目标/时间窗只重评约束，不重置旧真实轨迹；逆求结果的 `uncertain` 和 `not-found-within-search` 原意不变。
- I01/I04 手动 B 的 ramp 受物理约束，不因 UI 改成瞬时磁场；手势无效状态显示明确。
- I05/I06/I07 手动推拉过程中电流可以实时变化，松开后按真实物理状态变化；多点触控取消行为不丢失。
- C03 P07 屏幕命中和吸收是硬件事件，不可在 UI 中伪造光斑；C08 双棒接触后停止，不要假设碰撞并显示 1 J。
- 教师修改参数后，逐问参考答案与条件一起重算；固定文字公式不再适用时明确标记，不能继续以旧数字正确判题。

## 4. Track B：原生 App 开发方向（与 Web UI 收口并行评估，避免重写）

用户希望未来可以在 **Android 和 iPadOS** 上以 App 方式使用 EM Physics Lab，但当前 web-first 架构成本已经很高且物理求解完善。

**技术路线优先级：**

1. **Web + 可安装 PWA（当前主产品）**：先解决 HTTPS、首次安装、离线、真实设备交互和安全更新；保留离线教师草稿及学习记录。
2. **Capacitor 复用现有 React/Vite（推荐原生试点）**：将现有 `dist` 打包为 Android WebView/iOS WKWebView 容器，优先验证导航、WebGL、SVG 手势、数学软键盘、存储迁移、PWA SW 在 WebView 中的适配；同一物理计算代码继续使用。是否集成原生文件导入导出由真实需要决定。
3. **Google AI Studio Android Native 模式（独立技术原型）**：官方该模式输出 Kotlin/Jetpack Compose，不是对当前 React 源代码的无损“转换”。可以用它制作原生 UI/交互可行性样例，但不得宣称现有 16 个物理引擎已直接复用。**iPadOS 原生测试构建仍需 macOS/Xcode/签名条件**，不是 Build Android 模式的副产品。

### Track B 的实施指令

- 先检查当前项目是否已经存在 Capacitor、iOS/Android 原生工程，确认实际 Node/Android SDK/Xcode 可用条件。**不必为了演示新技术而改造稳定 PWA。**
- 对三条路线提交 `docs/NATIVE_APP_DECISION.md` 或对应在 Studio 可导出的文档，说明：实现成本、物理求解复用率、持久化行为、离线/WebGL 风险、对中国大陆学生分发的现实限制、可验证成果。
- 如果 Studio 能安全运行现有仓库的 Capacitor 工具链，并获得允许在试验分支新增目录的前提，可建立**独立、可撤销的 Android debug 原型**；不要申请无关权限，也不要接入强制联网 SDK。
- 如果 Studio 的沙盒不能编译 APK/IPA，仅产出可靠的工程步骤与变更文件并标记 `NOT_BUILT`；之后由 Codex 在 Android Studio/Xcode 环境完成。**不能把浏览器里的 Android 模拟器展示当作现有 React 完整原生应用构建成功。**
- 用户愿意探索 Kotlin 原生路线时，可在与当前产品隔离的独立原型中做单个实验控件与流畅度研究。除非后续明确决策，不得整体改写为 Kotlin/Compose，更不得删除 React app。

## 5. 分支同步与提交方式

默认批次完成流程：

1. 生成**小批量且容易审查**的代码 diff；简述改了哪些文件、为什么、使用了什么已有组件，给出前后截图（若工具能截取）。
2. 若 AI Studio 能执行项目命令，运行 `typecheck`、Vitest、Playwright、PWA、build 和 `verify:static`；若执行环境无法跑，明确 `NOT_RUN`，把 ZIP / diff 提供 Codex 在本地 CI 跑；**绝不能把 UI 预览成功叫做全量测试通过**。
3. 确认 GitHub push 的准确目标为 `ai-studio-dev` 后才可同步；若 UI 无法确认，**仅导出 ZIP**，交给 Codex 在 `ai-studio-dev` 上应用并做 PR。
4. 禁止直接合并到 `main`；经 Codex 对物理敏感文件进行审查、完整 CI 通过，才由用户批准 PR 合并。
5. 每批提供可回退的 commit SHA（如真的有提交）或 ZIP 的文件清单及变更摘要；不依赖 AI Studio 会永久保存聊天记忆。

若冲突提示涉及 `src/physics`、`package.json`、PWA/Service Worker、数据 schema，或者显示远端已有 Codex 新提交，不要直接用“Use my version”覆盖。先导出当前改动，向 Codex提供冲突文件清单，由单一主维护者做三方合并。

## 6. UI 和原生技术验收样例

- [ ] 首页四种入口均可跳至真实路由，没有 404 或虚构演示模型。
- [ ] P07 的 A/B/C 多粒子同台；A 正被编辑，B/C 时间仍继续；公共场改变所有粒子一起重算。
- [ ] 参数输入 `√3/2`、`1/3`、`π`、`5 T` 超滑块、`1/0` 非法输入的解析/显示/物理行为维持原义。
- [ ] C03 和 A17-01 能从完整题干到整题轨迹/事件再到逐问解析；变量变式后参考数值不是陈旧答案。
- [ ] I05/I07 手动拖动与反弹真实事件不因触控/底部面板重排而失效。
- [ ] 教师草稿导入/编辑/预览/导出保留，私有原文不进入构建和 PWA precache。
- [ ] 页面四种平板视口没有横向滚动、遮挡关键控件、公式溢出；软键盘打开时可继续编辑数值。
- [ ] P01 真 WebGL/降级模式、离线二次进入、hash 深链在可能的测试环境下仍正常。

### 可复现的发布/原生验收

- [ ] Studio 提供的是现有仓库的可审查改动，而不是新建一个不兼容的项目。
- [ ] 没有向 `main` 直接推送；`ai-studio-dev` GitHub 目标被实际确认，或仅使用 ZIP fallback。
- [ ] 没有未经授权的云部署、API 费用、密钥泄露、题目/学生数据收集。
- [ ] Android debug APK 只有具备真实构建证据才写 `NATIVE_BUILD_VERIFIED`；否则 `NOT_BUILT`。
- [ ] iPadOS/Android 真实设备触控及性能只用用户真实测试记录标为 `PASS`；CDP/模拟器要标 `SIMULATED`。
- [ ] `main` 的 16 模型/132 练习/9 原创综合题和旧存档键完全没有被重置。
