# 技术决策记录（DECISIONS）

日期：2026-11-01（2026-11-02 追加 I04 与路由分包）。记录会在后续阶段被更新；以当前代码和测试为准。

## D01 技术栈：React + TypeScript + Vite

**选择**：React 19、TypeScript、Vite、React Router（HashRouter）、KaTeX、`vite-plugin-pwa`。
**理由**：仓库为空，需求明确建议这条无服务器路线；TypeScript 利于物理引擎和数据 schema；Vite 构建快、PWA 插件成熟。
**代价**：初始 JS 曾是可包含 React + KaTeX 的单包（约 827.53 kB / gzip 258.45 kB）；2026-11-02 已对模型页、练习页与进度页做路由懒加载。第八轮后入口约 307.37 kB（gzip 96.57 kB）；P01/I01 chunk 48.09/47.43 kB（gzip 14.95/15.21），I02 chunk 54.14 kB，P06 chunk 59.42 kB。I04 首屏仍包含 KaTeX/教师/练习依赖，后续可继续细分。

## D02 图形：SVG 舞台，不用 Three.js / Canvas

**选择**：交互舞台全部用 SVG 绘制；物理计算不直接依赖屏幕坐标。
**理由**：首版重点是可拖动几何元素、圆心/半径/边界/文字标签与触控命中；SVG 在这些方面稳定且可检查。轨迹点数受控（≤150 个采样），无需 Canvas 高频绘制。
**代价**：极端长轨迹或粒子群模型的性能空间有限；如后续 P07 等模型需要，可单独引入 Canvas 层。

## D03 状态与播放时钟

**选择**：局部 React state + 自定义 hooks；不引入 Zustand。播放使用 `requestAnimationFrame` 推进“示教进度”，物理时间由解析式或预先算好的确定性仿真数组给出。
**理由**：P02 有解析解，I03 状态可确定性复现；暂停/拖动时间轴/关键帧不改变物理参数。避免用帧间隔直接积分物理。
**代价**：每帧会使页面局部重渲染；目前场景节点数量可控。已把静态曲线路径、磁场网格等用 `useMemo` 缓存。未来如需更低功耗，可将舞台播放状态放到独立 store 或 canvas。

## D04 P02 使用示教尺度 + 周期归一化慢放

**选择**：UI 质量 `10⁻²⁶ kg`、电荷单位 `e`、速度 `10⁶ m/s`；内部转换 SI；动画约 8 秒播放 2T，界面明确标注慢放与真实周期。
**理由**：如果直接使用电子质量，半径~微米、周期~皮秒，既不可见也不便于高中参数操作；如果使用纯虚拟数字又违反“SI 物理”要求。这套尺度兼顾可读性与真实公式。
**代价**：学生会看到实际周期为几百纳秒；通过“示教尺度”说明和真实 SI 显示避免误解。

## D05 I03 磁场为竖直无限长条形区域

**选择**：场区为 `[b1, b2]`、y 方向无限；线框刚体水平平移。
**理由**：与高中“进入/离开一条边界”的核心模型一致；上下边安培力可严格成对抵消，净力只来自竖直边，讲解更干净。
**代价**：不覆盖有限高度场区、反向磁场分区、磁场边缘效应与复杂真题。这些在 P04/I05/I07 或后续规格中处理。

## D06 真实安培力：逐段求和而不是“每边阻力”

**选择**：用 `dF = I dl × B` 的逻辑计算净力；上下边竖直力成对抵消；只有处于场内的竖直边产生净 x 力。
**理由**：避免在一条边上重复计算力，也避免把“每条边都有动生电动势”误当成总电动势。
**证据**：测试核对 `|F| = B²H²v/R`，方向始终阻碍运动；自由滑行能量损失与焦耳热一致。

## D07 自由滑行积分：固定步长 RK4

**选择**：`dt = 0.2 ms`，记录间隔 3 步；最长 12 s；事件阶段检测；停止条件为离开或速度/力同时趋零。
**理由**：单区域匀速场下的动力学足够平滑；RK4 精度高于显式欧拉，且便于能量校验。
**代价**：边界事件时间受步长限制；可通过减小步长提高，但会增加计算成本。关键帧会把状态重新计算并显示符号，不依赖手填。

## D08 教师视图采用舞台下方 dock，而非覆盖层

**选择**：教师模式下隐藏参数/讲解面板，舞台扩展为单列；公式与关键数据放在舞台和播放条之间的横向 dock。
**理由**：最早版本的浮层会遮住轨迹、拖拽把手和部分圆；dock 保证大图完整，且适合投屏。
**代价**：竖向高度有限时舞台略矮；已在竖屏限制教师舞台高度，避免播放条被推得太远。

## D09 I03 使用专用“拖动线框”把手

**选择**：线框本体不直接拦截大范围拖动，改用在框下方的一个大触控把手；磁场右边界另有把手。
**理由**：如果整个线框吸收 pointerdown，双指缩放很容易因为一指落在框内而失效。专用把手在保证拖拽功能的同时让舞台其余区域留给了 pinch/pan。
**代价**：需要一次点击把手而非直接拖线框本身；把手有清晰标签，参数面板也有精确的 x 输入。

## D10 本地进度：localStorage，而非 IndexedDB

**选择**：`localStorage` 键 `emplab.progress.v1`，通过 `useSyncExternalStore` 同步；支持 JSON 导出/导入、清空。
**理由**：首版只有 12 道题的少量记录，localStorage 足够且无需额外依赖；隐私面更简单。
**代价**：不适合大规模题库/图片缓存；清除站点数据会丢失记录；没有跨设备同步。后续题库扩大时可迁移到 IndexedDB。

## D11 内容合规：原创题与未核验真题索引严格分开

**选择**：
- 练习页只发布 `original` 且 `verified: true` 的原创题；
- 真题索引独立 tab，全部 `verifiedOnline: false`，不包含题干/答案/图片；
- 每题保留 `licenseNote` 与题源状态字段。
**理由**：真实试卷的授权、参数与答案在当前环境未能核实，不能编造，也不能把原创题标记为真题。
**后续**：必须对照权威原卷和可信解析，取得适当授权后才能录入受版权保护内容；数据 schema 已预留 `licensed_exam` 与 `unverified`。

## D12 测试策略

**选择**：Vitest 覆盖物理引擎、题库 schema、练习交互和页面冒烟；Playwright（本机 Chrome）覆盖多视口、触控 pinch、播放/事件/进度持久化；单独 PWA 配置在 `vite preview` 上验证 Service Worker 和离线重新加载。
**理由**：物理正确性优先；真实浏览器验证布局与触摸手势，不依赖 jsdom 的 CSS 能力。
**代价**：Playwright 使用视口模拟与 CDP 触摸，不等于真实 iPad/Android 手感和渲染；尚未做真机测试。

## D13 HashRouter 与静态部署

**选择**：`HashRouter`；URL 使用 `/#/...`。
**理由**：无需为静态托管配置 SPA fallback；离线场景下 hash 路由不会请求额外服务器路径。
**代价**：URL 形式不如 history 路由美观；未来若需要更好的可分享性，可在部署层配置 rewrite 后切换。

## D14 PWA 构建与图标

**选择**：`vite-plugin-pwa`（generateSW，autoUpdate）；图标由项目内 Node 脚本绘制并生成 192/512/maskable/apple-touch 图标；KaTeX 字体随构建本地打包。
**理由**：离线需要内置模型、KaTeX 字体和原创题；避免第三方 CDN；图标为原创几何图形。
**代价**：每次构建预缓存约 2.34 MB（91 项，含 P01/P02/P03/P06/I01/I02/I03/I04 与懒加载路由 chunk）；离线更新策略为自动更新，不提供手动版本提示。

## D16 播放中的初始条件探索（P02，2026-11-01）

**问题根因**：P02 页面在参数变化的副作用里调用 `clock.reset()`，它把 `playing` 置为 false 并将时间归零；舞台手柄又在 pointerdown 调用 `onSceneInteractionStart={clock.pause}`。因此参数一改就必然暂停。

**决策**：
- 在播放时钟中增加 `restart()`：只把时间归零，保持当前播放/暂停状态；
- 手柄编辑采用显式会话：记录编辑前播放状态、暂停并显示完整预测轨迹、松手后从新初态发射并按原状态恢复；
- 滑块、数值框、预设直接重算并归零，同时保留播放状态；
- 所有条件修改都显示“按新初始条件重算”的状态提示；
- 对手柄拖动增加第二次触点取消逻辑，避免双指缩放过程中误改入射点；
- 对 model 参数的 localStorage 写入做 180ms 去抖，减少连续拖动时的同步写开销。

**边界**：I03 本轮没有改成同样的实时编辑语义（仅回归测试）。P03 在后续轮次新增为真实的半平面有界磁场模块（见 D17）。P02/P03 仍不支持“粒子运动中连续改变外场”；I04 的连续手动调磁只改变固定线圈所处的 B(t)，不涉及粒子轨迹连续穿越变化磁场（见 D18）。**第五轮已用 D19 替换 P02/P03 单粒子编辑的全局暂停/归零语义**：restart 机制仍在，但只重发射目标粒子。

## D17 P03 半平面有界磁场（2026-11-01 追加）

**选择**：
- 新模块使用无限直线边界与半平面匀强磁场；方程采用任务书约定 `ω=−qBz/m`、`c=re+(−vey/ω, vex/ω)`、`r(τ)=c+Rot(ωτ)(re−c)`。
- 场外直线、场内圆弧、离场后直线构成解析分段解；UI 只采样解析解，不做贝塞尔拟合。
- 入场只接受正时间、正法向速度的横截穿越；边界平行时用洛伦兹力的法向加速度区分相切向内/向外。出场只接受沿真实旋转方向、法向速度指向场外的第一个边界交点；相切接触单独标记，不能当作 exit。
- 入场/边界的法向速度使用尺度相关容差，避免 UI 的 90° 方向因 `cos 90°` 浮点残差被误判成微小穿越；空间/相切容差与数值依据记录在 PHYSICS_SPEC。
- 核心求解器接受任意单位法向；本版 UI 仅提供竖直边界、场区在右侧，以控制平板界面复杂度。边界拖动是实验设置重算，不是时变磁场。
- 复用 P02 的 `restart()` 和实时编辑语义：手柄拖动时暂停并展示完整预测轨迹，松手后按原播放状态恢复；滑块/预设直接重算且保留播放状态。
- P03 教师视图增加紧凑图层开关栏（含公式显隐），位于舞台下方 dock，避免遮挡大图。

**代价**：单边界、单一匀强场，不支持有限矩形/反向分区/电场/中心力/碰撞；边界固定竖直；入场阈值对极端近切向速度采用平滑近似而非数学上无限接近的极限。

## D18 I04 时变磁场与连续手动调磁（2026-11-02 追加）

**选择**：
- 新增独立纯函数模块 `physics/induction/timeVaryingField.ts`，把 `evaluateWaveform`、`evaluateInduction`、`sampleInductionSeries` 与手动时间序列严格分层；React 页面不自行猜符号或电流方向。
- 波形：恒定、线性、正弦、三角波。线性/正弦使用解析导数；三角波在折点返回 `dbdt = null` 及左右斜率，UI 明确显示“不可导”，不伪造唯一值或零电流。
- 手动调磁是真实连续过程：相对拖动 → 目标 B → 0.4 s 仿真时间线性 ramp → 实际斜率决定 ε。斜率上限 4 T/s；停止后 B 保持、ε/I 回到 0。它不是把预设波形重置到 t=0，也不用逐帧差分制造导数。
- 手动模式固定 1× 实时（`usePlaybackClock` 新增 `realTime` 选项），与预设波形的“约 8 秒示教演示”区分；暂停时禁止记录手动变化。
- 电流方向、ε 符号、图形和箭头来自同一 `evaluateInduction` 结果；断开回路只把 I 置零，保留 ε。
- 路由层对 P02/P03/I03/I04、练习页和进度页使用 `React.lazy` + `Suspense`，工作箱预缓存所有 chunk，保证离线可用。

**代价**：手动导数有约 0.4 s 跟随延迟且为估计值，未使用真实传感器；不支持自感、互感、电容、辐射、复杂电路、线圈旋转或非均匀场。I04 首屏仍包含 KaTeX/练习/教师依赖，尚未在低端平板实测 60 fps。


## D19 P02/P03 多粒子场景与单粒子实时重发射（2026-11-02 追加）

**选择**：
- 新增通用 `physics/particles/multiParticle.ts`：稳定 ID、1–5 粒子、A–E 标签/颜色/线型、独立初态与 launchTime、添加/复制/删除/选择、草稿/提交/取消、单粒子/全部重发射、共享场重置。React 页面只负责 UI 与视觉会话。
- P02/P03 各自保留原解析求解器，仅新增场景适配器（`p02Scene.ts`、`p03Scene.ts`）；每个粒子用同一共享场独立求解，不创建多画布或复制页面。
- 全局时钟 `tGlobal` + 每粒子 `launchTime`；`τ=tGlobal−launchTime`，未发射不绘制伪位置。默认单 A、launchTime=0。
- 单粒子手柄编辑只创建草稿，不暂停/不归零全局时钟；指针移动只重算目标粒子，松手只令目标粒子从当前 tGlobal 重发射。B/C 的初态、launchTime、轨迹缓存与运动连续性保持。取消/第二指/切换选择丢弃草稿且不重发射。
- 单粒子数值框/预设只重发射目标；教学与练习的单粒子预设明确替换为单 A 场景，多粒子题目使用独立 `p02-multi-*` / `p03-multi-*` 预设。
- 共享 B（P02/P03）或边界（P03）是全场实验条件变化：P03 边界拖动先冻结时钟做全场预览，提交后 launchTime 全归 0、tGlobal=0、按原播放意图同步重放；取消则恢复原场。P02 的 B 面板修改直接同步重置。
- 场景版本 2 持久化 field/particles/runtime/active；旧 v1 单粒子参数迁移为 A；刷新时不恢复运行时间，t=0 重建；收藏/错题/进度独立保留。场景 JSON 导出带版本，导入对非法/超限/NaN 安全失败。
- 视觉轨迹清除只记录显示起点，不改变物理状态或 launchTime；同初态粒子不人为偏移以避免重叠。

**代价**：粒子间无相互作用/碰撞；最多 5 个；launchTime 是会话时间语义，不保留粒子多次编辑历史；刷新后所有 launchTime 归 0；共享场变化必须整场重放，不能做连续时变场（仅 I04 支持连续调磁）；真实 iPad/Android 5 粒子教师全矢量帧率尚未验证。


## D20 P06 电磁复合场：解析叠加与分段事件（2026-11-02 追加）

**选择**：
- 模式 A 用纯函数 `crossedFields.ts` 实现均匀静态 E+B 的解析状态、受力、动能/功和稳定小 B 展开；`Bz=0`、纯 E、纯 B、q=0 与匹配漂移速度均作为极限/退化测试。

- 切换同区/分段模式视为更换实验定义，载入对应的单粒子示例场景；模式 A 的场参数与模式 B 的 E/B/d 均为公共场，修改后全部粒子同步重演；单粒子初态修改只重发射该粒子。

**代价**：模式 B 只有三段竖直边界，没有任意多边形、时变场、点电荷中心力或碰撞；模式 A 用理想 SI 演示参数（如 1 kg/1 C），不是真实电子/质子装置；没有真实 iPad/Android 60 fps 数据。

## D21 I02 单导体棒：四模式解析与连续手势（2026-11-02 追加）

**选择**：
- 模式 A/B/C 由 `movingRod.ts` 的纯函数解析求解：匀速、自由滑行指数解、恒力解；`ε=−BzLv`、`I=ε/R`、`F_Bx=−(Bz²L²/R)v`、`P_J=kv²` 和能量量全部来自同一快照。
- 自由滑行能量使用 `K+Q_J=K(0)`；恒力模式独立计算解析 `Q_J`、`W_ext` 与残差，不用 `W−ΔK` 反向伪造热量。

**代价**：只支持静态均匀 E/B、二维目标线段与单参数反求；不包含真实狭缝/吸收板/屏幕、时变/非均匀场、相对论、点电荷中心力或碰撞；逆求受扫描区间、241 点默认预算与候选上限 8 的限制；相切临界与不确定根不声称严格解析唯一。

## D33 I08：规定匀速 + 纯电阻负载 + 滑环交流（2026-11-04）

**选择**：
- 采用“法线与 B 的夹角 θ”作为唯一角度定义；`Φ=BAcosθ`、`Ψ=NΦ`、`ε=NBAωsinθ`。UI 明确提示不是线圈平面角，避免 90° 相位错误。
- 自动 G1 是规定匀速 `θ=θ₀+ωt`，不求解角加速度；机械输入功率由 `τ_drive=−τ_em` 给出。手动 G2 复用 I01 的角度解缠与时间戳速率估计，松手后 ω=0。
- 电路为纯电阻 `R_L+r`；开路保留 ε 但 I=P=τ=0；`R_L=0,r>0` 合法短路；`Rtot=0` 非法。滑环输出交流，不画换向器。
- 能量用解析 `∫sin²`（ω→0 用稳定级数），开关事件用 `circuitTimeline` 分段积分；不使用“把 Q 复制为 W”的伪守恒。
- 手动 RMS/能量标为估计，不冒充解析整周期值。

**原因**：I08 的教学核心是相位、峰值/有效值、负载能量与交流方向；这些都能由纯电阻规定转速模型精确给出。把发电机做成“自由转子 + 负载”会引入未建模的角动力学和自感，超出高中模型边界。

**代价**：不包含自感/互感、RLC、变压器、整流器、机械角动力学、磁路非线性或真实损耗；手动模式只能给估计值；真实设备未验证。

## Round 17 决策（2026-11-05）

1. **教师工作台独立于 16 模型注册表**：教师题目是内容编排层，不是第 17 个基础物理模型；模型矩阵保持 16/16。
2. **不开放自由求解器拼接**：新题只允许 A17-01/A17-02 两个白名单适配器；C01–C08 可复制但保留已核验适配器。未注册组合不显示“连续”。
3. **A17-01 采用三阶段真实状态交接**：A 阶段纯 E 解析、B 阶段有限磁场真实边界、C 阶段自由漂移；位置/速度/全局时间门槛 1e-9，本轮实测 0。没有用样条或分屏伪造。
4. **教师草稿不写入公开内容**：本机 `localStorage` 版本化存储，导入/导出显式、可校验；不进入构建、precache 或诊断。
5. **答案不持久化旧基线**：编译时从当前求解器重新取值，教师题判题依赖覆盖全部变式键，避免参数变化后的陈旧答案。
6. **验证与权利分离**：`simulation_verified` 不提升 `sourceReview` 或 `rights`；未获授权真题只允许本机私有预览。
7. **发布诚实**：新增 release manifest 等本地交付物，但没有托管授权，HTTPS 仍 `BLOCKED`；没有真机，硬件项仍 `NOT_TESTED`。

## D39 发布门禁：变式推导默认折叠 + 完整本地备份（2026-11-06）

**选择**：
- 当某问的答案依赖参数被变式改变时，整题工作台默认折叠标准题设推导；学生/教师必须显式点击“仍查看标准推导（仅参考）”才看到旧文本，参考值与判题继续使用当前求解器结果，无唯一值返回 `needs_review`。
- “我的记录”新增完整本地备份：场景、132 题、案例进度、教师草稿、讲解/模式、设备自测；排除临时案例备份/返回上下文；按同名键覆盖、预览确认、写入失败回滚，不调用 `localStorage.clear()`。

**原因**：发布后最难解释的错误是“旧标准推导被当作当前答案”，以及教师草稿/场景在换设备或原生壳中丢失。默认折叠与可恢复备份能把风险降到可说明、可恢复。

**代价**：教师/学生需要多一次点击才能查看标准推导；备份文件可能包含教师私有题目，必须由用户妥善保管；跨 origin 迁移仍需人工操作。

**选择**：
